Alto Rooms v1

Spec · 2026-10-05 · author: jun-hash (with Claude Code) · repo: ~/personal/alto-rooms

0. Overview 🟡

Problem

코딩 에이전트와 브라우저 에이전트가 만든 HTML 아티팩트가 claude.ai, 로컬 폴더, 세션마다 흩어져서 누락되고, 너무 많고, 한곳에서 보기 어렵다. 직접 만든 결과물 대시보드는 66개 중 56개가 "기타"로 빠질 만큼 종류별 정리가 맞지 않았다. Television은 모아 보여주긴 하지만 등록 과정(CLI·스킬·경로 등록)이 불편했고 그룹핑 이상을 주지 못했다. Claude Artifacts는 결과물만 모아서 사람을 위한 이해 공간이 없다.

Goal (1줄)

어디서 만든 HTML 아티팩트든 폴더에 넣기만 하면 방별로 훑어보고, Journal에서 하루를 이해할 수 있다 — 코어는 어떤 에이전트·스킬·UI와도 결합하지 않는다.

원칙 (모든 결정의 기준)

  1. Rooms = HTML 아티팩트 저장소 + 나를 위한 이해 공간(Journal). 아티팩트를 만들지 않고, 에이전트를 돌리지 않는다.
  2. Rooms는 AI 일을 직접 하지 않는다. 미래 기능(묻기, 관계 시각화, 설명 채우기)도 맥락을 꾸려 사용자의 메인 에이전트에게 넘기고(또는 만든 세션을 이어 열고), 결과는 파일로 다시 받는다.
  3. 접점은 세 개뿐이고 모두 버전 붙은 고정 계약이다: 폴더 규칙(들어옴) · Rooms 프로토콜(코어↔UI) · 넘기기(나감, v2).
  4. UI도 갈아끼울 수 있다. 데스크탑 앱은 프로토콜만 쓰는 참고 클라이언트다 (Codex CLI의 코어/UI 분리 수준).
  5. 모든 단어·요소·배치에는 이유가 있어야 한다. 이유가 약하면 뺀다.

Out of scope (v1)

  • 묻기 (아티팩트에서 질문 → 만든 대화로 전달) — v2. 단, 만든 곳 메타데이터는 v1부터 읽어 둔다.
  • 방 안 아티팩트 사이 관계·한 줄 설명 시각화 — 후속 이슈.
  • 방 삭제, 방 안의 내 노트, HTML 외 파일, 휴대폰에서 쓰기(묻기·노트).
  • 동기화(Drive·Dropbox·git이 담당), 다중 사용자·인증, 에디터 기능(서식·블록).
  • 아티팩트 생성 스킬·Dream 루틴의 내장 — 둘 다 Rooms 바깥(어떤 스킬이든).
  • 배경 사진·장식적 "편안함" 처리 (시도 후 기각).

1. Requirements (User Stories) 🟡

User Stories

  • US-1. As a 사용자, I want 어떤 에이전트가 방 폴더에 HTML을 쓰기만 하면 앱에 바로 뜨기를, so that 등록·설치 없이 모든 결과물이 한곳에 모인다.
  • US-2. As a 사용자, I want 사이드바 +로 방을 만들고, 방 제목을 눌러 이름을 바꾸기를(자동 저장), so that 주제를 내 방식대로 나눈다.
  • US-3. As a 사용자, I want 이미 쌓아 둔 폴더(팀 폴더 포함)를 방으로 연결하기를, so that 파일을 옮기지 않고 그대로 본다.
  • US-4. As a 사용자, I want 방의 아티팩트를 큰 미리보기 가로 띠로 훑고, 확대하면 새 탭으로 열기를, so that 무엇이 있는지 빠르게 파악하고 궁금한 것만 깊이 본다.
  • US-5. As a 사용자, I want Journal에서 그날 생긴 아티팩트(Dream 포함)와 내 계획·회고를 함께 보기를, so that 하루를 이해하고 정리한다.
  • US-6. As a 사용자, I want 다른 기기에서 Tailscale로 같은 화면을 읽기 전용으로 보기를, so that 맥 앞에 없어도 확인한다.
  • US-7. As a 제3자 개발자, I want Rooms 프로토콜만으로 내 UI를 만들기를, so that 코어를 건드리지 않고 다른 경험을 붙인다.

2. Business Logic & Policy 🟡

Core Rules

  1. 폴더 규칙(들어옴): 방 폴더(하위 포함)의 .html/.htm = 아티팩트. 그 외 확장자는 무시. 예외: Journal day 폴더의 .md = 노트.
  2. 무시 규칙: 숨김 파일·폴더(.로 시작), node_modules, dist, build, .next, coverage. linked 방은 폴더 안 .gitignore를 따른다. 사용자가 직접 둔 .roomsignore(gitignore 문법)를 따른다. Rooms는 .roomsignore를 스스로 쓰지 않는다.
  3. 메타데이터는 선택: 제목 = <meta name="rooms:title"> → <title> → 파일 이름. 시각 = rooms:created → 처음 본 시각 기록(.rooms/index.json, 첫 발견 때 파일 생성 시각 → 수정 시각으로 정하고 이후 고정). 만든 곳 = rooms:agent, rooms:session, rooms:cwd, rooms:machine (없으면 비움, v2 묻기용).
  4. owned vs linked: owned = Home 하위 실제 폴더, 이름 바꾸기 = 폴더 이름 변경. linked = 경로 참조, 이름 바꾸기 = 표시 이름만. Rooms는 linked 폴더 안에 어떤 파일도 쓰지 않는다.
  5. Rooms 상태 위치: 방 id·표시 이름(owned 포함)·연결 경로·owned 폴더 inode·방 순서는 ~/rooms/.rooms/state.json, 아티팩트 첫 발견 시각은 ~/rooms/.rooms/index.json. 보는 사람 상태(지난 방문, 사이드바 접힘, 탭)는 클라이언트가 가진다 — 코어는 보는 사람을 모른다.
  6. Journal: journal은 예약된 방 이름. Journal day = journal/YYYY-MM-DD/ 폴더(없으면 노트 저장 시 생성) + 그날 생긴 다른 방 아티팩트 조회(복사 안 함).
  7. 쓰는 주체: 아티팩트 = agent, Journal 노트 = me. 데이터 모델에 author 칸을 두어 나중에 방에도 내 노트를 넣을 수 있게 열어 둔다.
  8. 방 삭제는 없다. 연결 해제도 v1에 없음 (필요해지면 추가).
  9. 원격(Tailscale) = 읽기 전용. 원격 리스너(4319)에는 GET 경로만 존재. 쓰기는 로컬 리스너(4317)에서 토큰과 함께만.
  10. 코어에는 모델·프롬프트·API 키·UI가 없다.

노트 저장 중 디스크 오류500 write_failed, 클라이언트는 편집 내용 유지 후 재시도"저장하지 못했어요. 다시 시도할게요"error

Recovery / Retry Policy

파일 시스템이 진실이므로 코어 인덱스는 언제든 재스캔으로 복구된다. 시작 시 전체 스캔, 실행 중 감시, 오버플로 시 방 단위 재스캔. 노트 저장 실패는 클라이언트가 지수 백오프(1s·2s·4s, 최대 3회) 후 사용자에게 알림. SSE 연결이 끊기면 클라이언트는 재연결 후 GET으로 스냅샷을 다시 받는다(이벤트 재생 없음).

5. Seams (edge — 경계 계약) 🟡

§4 화살표 하나 = seam 하나. call-site 먼저 → frozen signature → 3줄 계약.

Seam Index

S1: Producer → Folder (폴더 규칙)

아무 에이전트·스크립트·사람이 Rooms에 아티팩트를 넣는 유일한 방법. 설치·등록·전용 스킬 없음.

Call-site
# 어떤 producer든 — 쓰기만 하면 끝
cp benchmark.html ~/rooms/브라우저-하네스/
# 또는 에이전트에게: "결과 HTML을 ~/rooms/브라우저-하네스/ 에 저장해"
# Dream: 아무 스킬이 밤에
write ~/rooms/journal/2026-10-05/dream.html
Frozen signature (파일 규칙 v1)
path:   <room-folder>/**/<name>.html|.htm      # 무시 규칙 밖
        ~/rooms/journal/YYYY-MM-DD/<name>.html # Journal day 아티팩트
optional <head> meta (모두 생략 가능):
  <meta name="rooms:title"   content="…">
  <meta name="rooms:created" content="2026-10-05T10:02:00+09:00">
  <meta name="rooms:agent"   content="claude-code|codex|…">

경계 계약
건너감↓ HTML 파일 하나(선택적 meta). ↑ 없음 (producer는 Rooms를 모른다)
제어·상태 소유producer가 파일을 소유. Rooms는 읽기만 (owned 방 폴더 생성·이름 변경 제외, linked는 절대 쓰지 않음)
상대편 보장파일이 HTML 확장자를 가지고 무시 경로 밖에 있으면 Rooms가 2초 안에 보여준다. 메타가 틀리거나 없어도 fallback으로 반드시 보인다

S2: Folder → RoomsCore (해석)

파일 시스템을 도메인 값(Room/Artifact/JournalDay)과 변경 이벤트로 번역.

Call-site (roomsd 안)
const core = await openRooms({ home: "~/rooms" });
const rooms = core.listRooms();                 // Room[]
const items = core.listArtifacts(room.id);      // Artifact[]
const day   = core.getJournalDay("2026-10-05"); // JournalDay
const off   = core.onChange((e) => sse.broadcast(e)); // RoomsEvent
Frozen signature
export function openRooms(opts: { home: string }): Promise<RoomsCore>;

export interface RoomsCore {
  listRooms(): Room[];
  listArtifacts(roomId: RoomId): Artifact[];          // createdAt 오름차순
  getJournalDay(date: IsoDate): JournalDay;
  createRoom(name: string): Promise<Room>;            // owned
  linkFolder(path: string, name?: string): Promise<Room>;
  renameRoom(roomId: RoomId, name: string): Promise<Room>;
  saveNote(date: IsoDate, name: NoteName, body: string): Promise<Note>;
  resolveFile(roomId: RoomId, relPath: string): string; // 절대경로, 방 밖이면 throw
  onChange(listener: (e: RoomsEvent) => void): () => void;
  close(): Promise<void>;
}
경계 계약
건너감↓ Home 경로 / 이름·경로·노트 본문. ↑ 순수 값 타입(protocol 패키지의 타입)과 RoomsEvent
제어·상태 소유core가 인덱스(메모리)와 .rooms/state.json을 소유. 파일 시스템이 진실, 인덱스는 언제든 재구성 가능
상대편 보장모든 반환값은 protocol 스키마를 통과한다. resolveFile은 방 밖 경로(.., 심볼릭 링크 탈출)를 절대 반환하지 않는다

S3: roomsd → Client (Rooms Protocol v1)

UI를 갈아끼울 수 있게 하는 허리. 데스크탑 앱도 이것만 쓴다.

Call-site (아무 클라이언트)
const rooms = createRoomsClient("http://127.0.0.1:4317");
const list  = await rooms.listRooms();
const strip = await rooms.listArtifacts(list[0].id);
rooms.subscribe((e) => { if (e.type === "artifact.added") refresh(e.roomId); });
await rooms.renameRoom(id, "연구 도구");          // 로컬만, 원격은 403
iframe.src = rooms.fileUrl(artifact);            // /v1/files/:roomId/:relPath
Frozen signature (HTTP)
GET    /v1/info                         → { version: "1", readOnly: boolean, home: string,
                                            journalRoomId: "journal", filesOrigin: string }
GET    /v1/rooms                        → Room[]
POST   /v1/rooms        {name}          → Room            (owned)
POST   /v1/rooms/link   {path, name?}   → Room            (linked)
PATCH  /v1/rooms/:roomId {name}         → Room
GET    /v1/rooms/:roomId/artifacts      → Artifact[]
GET    /v1/journal/:date                → JournalDay      (date = YYYY-MM-DD)
PUT    /v1/journal/:date/notes/:name    text/markdown → Note
GET    /v1/rooms/journal/artifacts      → 모든 날짜의 journal/*/*.html (createdAt 오름차순)
GET    {filesOrigin}/:roomId/*relPath    → 파일 원본. 별도 포트(4318) = 별도 origin
                                           CSP: sandbox allow-scripts allow-popups (allow-same-origin 없음)
GET    /v1/events                       → text/event-stream of RoomsEvent (각 이벤트에 seq)
모든 스냅샷 GET 응답 헤더: X-Rooms-Seq: <그 시점 seq>
쓰기(POST/PATCH/PUT) 조건 = loopback 요청 AND Host ∈ {127.0.0.1:4317, localhost:4317}
  AND Origin ∈ 허용 목록(데스크탑 앱 origin) AND Authorization: Bearer <실행마다 새 토큰>
  (토큰은 roomsd가 ~/rooms/.rooms/token(0600)에 쓰고 Tauri가 읽어 전달) — 아니면 403
경계 계약
건너감↓ 방 이름·경로·노트 본문. ↑ JSON 값(Room/Artifact/JournalDay/Note)과 SSE 이벤트, 아티팩트 파일 바이트
제어·상태 소유roomsd가 서버 상태(인덱스) 소유. 보는 사람 상태(지난 방문·탭·사이드바 접힘·토글)는 클라이언트 소유. 방향: 클라이언트 → roomsd 요청, roomsd → 클라이언트 이벤트
상대편 보장/v1 안에서는 필드 추가만 하고 삭제·의미 변경 없음. 모든 이벤트는 단조 증가 seq를 가진다. 클라이언트 규칙: ① SSE 먼저 연결해 이벤트를 버퍼 ② 스냅샷 GET(X-Rooms-Seq) ③ 버퍼에서 seq ≤ 스냅샷 seq는 버리고 나머지 적용 ④ 적용은 항상 id 기준 upsert/delete(멱등). 재연결도 같은 순서. 아티팩트 HTML은 API와 다른 origin에서 sandbox로만 실행되어 API를 호출할 수 없다 (Q6, Q7)

S4: core → 사용자 에이전트 (Handoff, v2 — 예약만)

v1에서는 구현하지 않음. 형태만 고정해 v2가 데이터 변경 없이 붙게 한다.

Call-site (v2)

// 설정: agentCommand = 'claude --resume {session} -p {prompt}' (session 없으면 새 세션 템플릿)
Frozen signature (예약)
type HandoffRequest = { kind: "ask"|"describe"|"relate"; roomId: RoomId;
  artifactIds: ArtifactId[]; prompt: string };
// 결과는 반환하지 않는다. 에이전트가 S1(폴더)로 HTML/meta를 다시 쓴다.
경계 계약
건너감↓ 맥락 꾸러미(파일 경로·메타·질문). ↑ 없음 (결과는 S1으로 돌아옴)
제어·상태 소유사용자가 에이전트 명령 템플릿을 소유. Rooms는 명령을 실행만 하고 AI 상태를 갖지 않는다
상대편 보장에이전트는 결과를 폴더 규칙(S1)대로 쓴다 — 그래서 Rooms는 출력 형식을 알 필요가 없다

리뷰 시 확인할 점 (seam 스멜)

S1에 Rooms 전용 명령·스킬이 끼어 있지 않은가(결합도 0)? S3 call-site가 core 내부(인덱스, 감시)를 몰라도 되는가? S4가 결과를 직접 받지 않고 S1으로 돌려받는 구조인가?

6. Contracts (node — Design by Contract) 🟡

Value types (packages/protocol)

type RoomId = string;      // 생성 시 발급(nanoid 12), 이름 바꿔도 불변
type ArtifactId = string;  // sha1(roomId + ":" + relPath) 앞 16자 — 이동하면 새 id
type IsoDate = `${number}-${number}-${number}`; // 로컬 날짜

interface Room { id: RoomId; name: string; kind: "owned"|"linked"|"journal";
  path: string; status: "ok"|"unavailable"; artifactCount: number; updatedAt: string | null }

interface Artifact { id: ArtifactId; roomId: RoomId; relPath: string; title: string;
  createdAt: string; updatedAt: string; author: "agent";
  source: { agent?: string; session?: string; cwd?: string; machine?: string } }

interface Note { date: IsoDate; name: string; relPath: string; updatedAt: string; author: "me" }

interface JournalDay { date: IsoDate; artifacts: Artifact[]; notes: Note[] }
  // artifacts = journal/date/*.html + 모든 방에서 createdAt 로컬 날짜 == date

type RoomsEvent = { seq: number } & (
  | { type: "room.added"|"room.updated"; room: Room }      // status: unavailable 포함
  | { type: "room.removed"; roomId: RoomId }               // owned 폴더가 바깥에서 지워짐
  | { type: "artifact.added"|"artifact.updated"; artifact: Artifact }
  | { type: "artifact.removed"; roomId: RoomId; artifactId: ArtifactId }
  | { type: "note.saved"; note: Note }
  | { type: "note.removed"; date: IsoDate; name: string }
  | { type: "journal.changed"; date: IsoDate }             // 그 날짜 day 구성이 바뀜 → 클라이언트는 day를 다시 GET
  | { type: "resync"; roomId?: RoomId } );                 // 클라이언트는 해당 범위 스냅샷 재요청

10.1 진입점-우선 워크스루

10.2 Senior Q&A

senior engineer 페르소나 subagent 리뷰 결과를 아래에 덧붙인다.

Q1. Journal 방의 id는 어디서 얻나

A. Journal의 roomId는 고정 상수 "journal"이고 GET /v1/info의 journalRoomId로 알린다. listRooms에는 넣지 않는다(사이드바에서 Journal은 방 목록 위 별도 항목). GET /v1/rooms/journal/artifacts는 모든 날짜의 journal/*/*.html을 createdAt 오름차순으로 돌려주고, 날짜별 보기는 /v1/journal/:date를 쓴다. §5 S3·§6에 반영.

Q2. day 불변은 재시작 후에도 지켜지나

A. 지킨다. 아티팩트를 처음 발견할 때 정한 createdAt을 ~/rooms/.rooms/index.json에 ArtifactId 기준으로 저장하고, 이후 재시작·임시파일 rename·동기화로 birthtime이 바뀌어도 저장값을 쓴다. 우선순위는 rooms:created 메타 → 저장된 첫 발견 시각 → (첫 발견 때만) birthtime → mtime. 이 파일은 Rooms 자체 상태라 linked 폴더를 더럽히지 않는다. §2에 반영, §11의 birthtime 질문은 해소.

Q3. Finder에서 바꾼 owned 폴더의 id

A. state.json에 owned 방마다 폴더 inode(dev+ino)를 저장해 매칭한다. 감시자가 unlink+add를 보면 같은 inode의 새 경로로 판단해 같은 id를 유지하고 표시 이름을 새 폴더 이름으로 갱신하며 room.updated 1회를 낸다. inode를 못 찾으면 room.removed. 앱에서 한 rename은 core가 그 방의 감시 이벤트를 rename 동안 억제하고 room.updated만 1회 낸다(ArtifactId는 roomId 기준이라 바뀌지 않음).

Q4. 삭제 이벤트가 없음

A. room.removed, note.removed를 추가했고, linked 폴더가 사라지면 room.updated(status: unavailable)로 알린다. Journal day는 클라이언트가 날짜를 계산하지 않도록 core가 영향을 받은 날짜마다 journal.changed {date}를 내고, 클라이언트는 그 날짜를 보고 있으면 day를 다시 GET 한다. §6 RoomsEvent에 반영.

Q5. 겹치는 방 경로에서 중복

A. 거부한다. 연결 경로는 realpath 기준으로 Home·Home 상위·Home 하위, 그리고 기존 linked 방의 상위·하위가 될 수 없고, 위반하면 overlapping_room(409)이다. 그래서 한 파일은 정확히 한 방에만 속하고 ArtifactId 중복이 생기지 않는다. §6 Inputs·Errors에 반영.

Q6. loopback 쓰기와 아티팩트 origin

A. 아티팩트 파일은 API와 다른 포트(4318) = 다른 origin에서 CSP: sandbox allow-scripts allow-popups(allow-same-origin 없음)로 제공해, 아티팩트 JS는 불투명 origin이라 API를 부를 수 없다. 쓰기는 loopback + Host 헤더가 127.0.0.1:4317/localhost:4317(DNS rebinding 차단) + Origin 허용 목록 + 실행마다 새로 만드는 Bearer 토큰(.rooms/token, 0600, Tauri가 전달)을 모두 만족해야 한다. 브라우저의 아무 웹페이지는 토큰을 모르므로 CSRF가 막힌다. §5 S3에 반영.

Q7. SSE 재연결과 스냅샷 사이 유실

A. 모든 이벤트에 단조 증가 seq를 붙이고, 스냅샷 GET은 X-Rooms-Seq 헤더로 그 시점 seq를 준다. 클라이언트는 SSE를 먼저 연결해 버퍼링 → 스냅샷 GET → 버퍼에서 seq ≤ 스냅샷 seq는 버리고 나머지 적용, 적용은 항상 id 기준 upsert/delete라 두 번 와도 안전하다. 재연결도 같은 순서. S3 상대편 보장에 클라이언트 규칙으로 명시.

Q8. owned 방 이름과 slug 왕복

A. 표시 이름 원문은 owned 방도 state.json에 저장하므로 재시작 후에도 "연구 도구"로 보인다. 폴더 이름은 NFC 정규화 후 공백을 -로 바꾼 slug이고, 충돌은 slug를 NFC·대소문자 무시로 비교해 판정하므로 "연구 도구"와 "연구-도구"는 같은 이름으로 보고 409를 낸다(APFS 기본 대소문자 무시와 일치). §2 불변식에 반영.
