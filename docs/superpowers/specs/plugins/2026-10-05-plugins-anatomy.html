Where should a plugin keep its data?

The app never imports plugin code. It reads a plugin folder at runtime and opens its index.html in a sandboxed iframe. The only open question here is where the plugin's own data (Excalidraw drawings, goals) lives.

Plugin anatomy
~/rooms/.rooms/plugins/excalidraw/
├─ manifest.json
├─ index.html ← built by the plugin's own repo
├─ assets/…
└─ data/ ← option A
manifest.json
{
 "id": "excalidraw",
 "name": "Excalidraw notes",
 "version": "0.1.0",
 "minAppVersion": "0.3.0",
 "slots": {
  "artifact.sidePanel": { "title": "Notes" }
 }
}
Plugin iframe
sandbox="allow-scripts", no network ⇄ postMessage ⇄ Plugin host (app)
checks the manifest, scopes every call ⇄ HTTP ⇄ roomsd
reads/writes files
A

Inside the plugin folder (recommended)

~/rooms/.rooms/plugins/<id>/data/. Plain files the plugin reads and writes through the host. Syncs with the rest of ~/rooms. Deleting the plugin folder deletes its data, as in Obsidian.

B

Separate data folder

~/rooms/.rooms/plugin-data/<id>/. Same as A, but reinstalling or removing the plugin keeps its data.

C

Next to the artifact

A drawing saved as <room>/report.excalidraw. Easy to find in Finder, but impossible in linked rooms (Rooms never writes there) and it only fits per-artifact data, not goals.
