Rooms Plugins v1

Spec · 2026-10-06 · author: jun-hash (with Claude Code) · repo: alto-computer/alto-rooms

0. Overview 🟡

Problem

Rooms는 Room · Artifact · Journal만 제공한다. 사람마다 그 위에 원하는 경험이 다르다 — 문서 옆에 Excalidraw로 필기하며 읽기, 장기·중기·단기 목표와 TODO를 관리하는 보드 등. 이것들을 기본 경험으로 넣으면 앱이 무거워지고 모두에게 같은 방식을 강요한다. 지금은 사용자나 기여자가 앱을 고치지 않고 화면을 확장할 방법이 없다.

Goal (1줄)

앱을 고치지 않고, 샌드박스 iframe 플러그인이 정해진 자리(slot)에 화면을 더하고 자기 데이터를 파일로 저장할 수 있다.

원칙

  • 화면 확장 = 플러그인, 내용 생성 = 에이전트. Dream 같은 생성은 사용자의 에이전트(astack·스킬)가 하고 결과를 폴더에 파일로 넣는다. 플러그인은 UI/UX만 확장한다.
  • 앱은 플러그인 코드를 import하지 않는다. 실행 시 ~/rooms/.rooms/plugins/<id>/를 읽어 띄울 뿐. 우리가 만드는 Excalidraw·Goals도 별도 저장소에서 공개 SDK만 쓴다 (dogfooding).
  • 좁게 열고 필요할 때 넓힌다. 샌드박스(Logseq·Figma식) + 선언형 slot(VS Code식) + 좁은 메시지 API. Obsidian식 전권 실행은 하지 않는다 — 플러그인이 쓰기 토큰을 가져가면 안 된다.
  • 파일이 진실. 플러그인 데이터도 Home 아래 평범한 파일. 에이전트도 읽고 쓸 수 있다.

Out of scope (v1)

  • slot: Journal 위젯(B), ⌘K 명령(D), 설정 페이지(E), 문서 탭 액션 버튼 — 모두 같은 구조로 나중에 추가 가능
  • 플러그인 마켓·레지스트리·자동 업데이트, 설치 UI (v1 설치 = 폴더 복사)
  • 플러그인 끄기·제거 UI (v1은 폴더 삭제 / §11)
  • 네트워크 접근, Artifact 본문 읽기, 다른 플러그인 데이터, 방·노트 쓰기 API
  • 플러그인끼리 통신, 탭 사이 드래그

1. Requirements 🟡

User Stories

  • US-1. As a 사용자, I want 문서를 보면서 옆 패널에 Excalidraw로 필기하기를, so that 읽으며 생각을 그 문서에 붙여 둔다.
  • US-2. As a 사용자, I want 사이드바의 Goals로 장기·중기·단기 목표와 TODO를 관리하고 관련 문서를 붙이기를, so that 문서들이 무엇을 위한 것인지 한눈에 본다.
  • US-3. As a 사용자, I want 새 플러그인이 처음 보일 때 무엇을 할 수 있는지 보고 켤지 정하기를, so that 모르는 코드가 몰래 돌지 않는다.
  • US-4. As a 기여자, I want SDK 하나와 폴더 규칙만으로 플러그인을 만들기를, so that Rooms 코드를 몰라도 내 UI를 붙인다.
  • US-5. As a 사용자의 에이전트, I want 플러그인 데이터를 평범한 파일로 읽고 쓰기를, so that "이 리포트를 이 목표에 붙여줘"를 처리한다.

2. Business Logic & Policy 🟡

Core Rules

  1. 발견: roomsd가 <home>/.rooms/plugins/*/manifest.json을 스캔(시작 시 + 폴더 감시). 폴더 이름 = manifest id여야 함.
  2. 켜짐: 처음 본 유효 플러그인은 pending. 사용자가 Turn on 하면 state.json의 plugins.enabled에 id 추가. 켜진 것만 iframe을 연다.
  3. 재확인: 켠 뒤 manifest의 permissions가 늘어나면 다시 pending (새 권한만 표시해 묻는다). 버전만 바뀌면 묻지 않는다.
  4. 실행: entry를 files origin(127.0.0.1:4318/_plugins/<id>/…)에서 sandbox="allow-scripts" iframe으로 연다. allow-same-origin은 절대 없음 → opaque origin (localStorage·쿠키·부모 접근 불가).
  5. 권한 → iframe 속성: clipboard → allow="clipboard-read; clipboard-write", downloads → sandbox에 allow-downloads. rooms.read → 브리지 rooms.list·artifacts.list 허용. 선언 안 한 능력은 열지 않는다.
  6. 네트워크·출처: files origin은 Artifact(신뢰 못 함)와 플러그인을 함께 서빙하므로 'self'를 쓰지 않는다. /_plugins/<id>/* 응답 헤더는 플러그인마다:
    Content-Security-Policy: sandbox allow-scripts[ allow-downloads]; default-src 'none'; script-src {P}; style-src {P} 'unsafe-inline'; img-src {P} data: blob:; font-src {P}; connect-src 'none'; frame-src 'none'; form-action 'none' ({P} = http://127.0.0.1:4318/_plugins/<id>/, 경로 한정). 헤더의 sandbox 토큰은 iframe 속성과 같은 manifest 권한에서 도출 — 지금 모든 응답에 붙는 sandbox allow-scripts allow-popups를 /_plugins에는 적용하지 않는다. 글꼴 등 자산은 플러그인이 직접 동봉.
  7. 저장: storage.*는 <plugin>/data/ 안의 상대 경로만. UTF-8 텍스트, 파일당 ≤ 10 MB. 원자적 쓰기(tmp → rename).
  8. 열기: open은 현재 탭에서 navigate (⌘ 등 수정키 없음 — 플러그인은 새 탭을 강제하지 못함). 대상은 room 또는 fileKey.
  9. 종료 전 저장: app://flush 때 열린 모든 플러그인 iframe에 beforeClose를 보내고 ack를 기다린다(전체 1.5 s cap, 노트 flush cap 2 s 안에서 병렬).
  10. 사이드바: tab slot에 sidebar: true면 사이드바 "Plugins" 구역에 항목이 생긴다. Plugins 구역은 그런 플러그인이 하나라도 켜져 있을 때만 보인다.

Recovery / Retry Policy

호스트는 재시도하지 않는다. 브리지 에러는 항상 플러그인에게 그대로 돌려주고, 재시도·표시는 플러그인이 정한다. iframe Reload는 사용자가 누를 때만. 앱은 플러그인 실패로 절대 멈추지 않는다.

4. Architecture (macro) 🟡

① 축: "플러그인이 무엇인가(roomsd 레지스트리·데이터)" vs "플러그인을 어떻게 띄우고 중계하나(PluginHost)" vs "플러그인 쪽 계약(SDK)". ② 허리: 플러그인과 앱은 브리지 메시지 하나로만 만난다. ③ 의존: 플러그인 → SDK → (메시지) → PluginHost → RoomsClient → roomsd. 역방향 import 없음. ④ 덩어리마다 facade 하나.

플러그인이 앱에 닿는 유일한 길. 공개 API의 전부.

Frozen signature (packages/plugin-sdk)
export function connect(opts?: { timeoutMs?: number }): Promise<RoomsPlugin>;

export interface RoomsPlugin {
  readonly pluginId: string;
  onContext(cb: (ctx: PluginContext) => void): () => void;      // 즉시 1회 + 변경마다
  onBeforeClose(cb: () => Promise<void> | void): () => void;
  storage: {
    read(path: string): Promise<string | null>;
    write(path: string, text: string): Promise<void>;
    list(prefix?: string): Promise<string[]>;      // data/ 기준 상대 경로, 정렬됨
    delete(path: string): Promise<void>;           // 없으면 no-op
  };
  rooms: { list(): Promise<PluginRoom[]> };         // rooms.read
  artifacts: { list(roomId: string): Promise<PluginArtifact[]> };   // rooms.read
  open(target: { roomId: string } | { fileKey: string }): Promise<void>;
}

export type PluginContext =
  | { slot: "artifact.sidePanel"; artifact: PluginArtifact }
  | { slot: "tab" };

export interface PluginRoom { id: string; name: string }
export interface PluginArtifact { roomId: string; artifactId: string; fileKey: string; title: string; createdAt: string }

export class PluginError extends Error {
  code: "permission_denied" | "invalid_path" | "too_large" | "not_found" | "write_failed" | "unknown_method" | "timeout";
}
Wire (SDK 내부, 문서화만 — 플러그인은 직접 쓰지 않음)
host → plugin  { rooms: 1, type: "context", context: PluginContext }
host → plugin  { rooms: 1, type: "beforeClose", id }
plugin → host  { rooms: 1, type: "ready" } | { rooms: 1, type: "beforeClose.done", id } | { rooms: 1, type: "pong", id }
plugin → host  { rooms: 1, id, method, params }      →   host → plugin { rooms: 1, id, result } | { rooms: 1, id, error: { code, message } }
host → plugin  { rooms: 1, type: "ping", id }        // 무응답 감지
경계 계약
건너감↓ 메서드 이름 + JSON params (경로·텍스트·roomId·target) / ↑ JSON 결과 또는 {code,message}. 토큰·URL·전체 state는 절대 건너가지 않음.
제어·상태 소유플러그인이 자기 UI 상태와 저장 시점을 소유. 호스트는 무상태 중계자 (요청마다 권한·경로 검사).
상대편 보장호스트: event.source === frame.contentWindow인 메시지만 받고 그 iframe에만 응답, context는 ready 직후 1회 + 변경 시마다, fileKey는 §2 불변식대로 안정. SDK: event.source === window.parent가 아닌 메시지는 전부 버린다 (옆 Artifact iframe이 parent.frames[i]로 context·응답을 위조하는 것 차단). 플러그인: beforeClose에 cap 안에 ack.

메서드paramsresult / 보장

경로 규칙 (호스트·코어 공통): 1–200자, 세그먼트 [A-Za-z0-9._-]+를 /로 연결, ./../빈 세그먼트·선행 / 금지, 깊이 ≤ 8. 텍스트 ≤ 10 MB (UTF-8 바이트).

Pre / Post

  • Pre: 플러그인 status ok + enabled; iframe이 ready를 보냄.
  • Post (write): 파일이 디스크에 완전히 있음(부분 쓰기 없음). 이벤트는 내지 않음 — 플러그인 데이터는 자기만 본다(외부 수정 감지는 v2).
  • Post (setPluginEnabled): state.json 저장 + plugins.changed 이벤트.

Flow Index

#흐름한 줄 책임진입점
1발견 → 켜기폴더에 들어온 플러그인을 묻고 켠다RoomsCore::plugins → EnableCard

흐름 1: 발견 → 켜기

① 트리거 & 타이밍

roomsd 시작 시 스캔 + .rooms/plugins/ 감시(디바운스 300 ms) → plugins.changed. 앱은 시작 시와 이벤트마다 listPlugins().

② 워크플로우

③ 입력 & 출처

입력출처전제
manifest.json플러그인 폴더폴더 이름 = id
plugins.enabled, plugins.grantsstate.json없으면 빈 목록
앱 버전Info.version—

④ 주요 결정

결정방식근거
켤지사용자 (카드)US-3. 자동 켜기 없음
다시 물을지결정론: 현재 permissions ⊄ 허락한 permissions(grants[id])권한이 늘 때만 묻기
카드 순서결정론: id 사전순, 한 번에 하나여러 개 동시 설치해도 차례로

⑤ 에러 & 폴백

manifest 오류·버전 초과 → status만 바뀌고 카드·렌더 없음. setPluginEnabled 실패 → 카드에 "Couldn't turn it on" + 다시 시도.

⑥ 동작 결과

enabled → usePluginItems·<PluginSlot>가 그 플러그인을 포함. Not now → 메모리에만 기록(이번 실행 동안 카드 숨김).

⑦ 연결

S4(스캔·state) → S3(listPlugins/setPluginEnabled) → S2(셸 자리).

흐름 2: slot 렌더 + 브리지

① 트리거 & 타이밍

문서 탭에서 ✎ Notes 열림 / 플러그인 탭 활성화 시 iframe 생성. 패널을 닫거나 탭을 떠나면 iframe 제거(beforeClose 먼저). 같은 패널에서 문서만 바뀌면 iframe 유지 + context 재전송.

② 워크플로우

  1. PluginSlot이 pluginEntryUrl로 iframe 생성 (sandbox·allow는 permissions에서 도출).
  2. SDK connect()가 ready 전송 → 호스트가 event.source로 iframe 식별 → context 전송.
  3. 요청 {id, method, params} → handleBridgeCall: 모양 검증 → 권한 → 경로 → RoomsClient → 응답.
  4. 호스트가 5 s마다 ping; 3 s 안에 pong 없으면 무응답 오버레이.

③ 입력 & 출처

PluginInfo(목록), 열린 Artifact(DocView), viewerStore(패널 열림·너비), 메시지(iframe).

④ 주요 결정

결정방식근거
메시지 출처 확인event.source === frame.contentWindow (origin은 opaque "null"이라 못 씀)다른 iframe(Artifact 포함) 위장 차단
open의 fileKey 해석코어 artifact_by_file_key, 여러 개면 사이드바 순서 첫 방결정론적
패널에 여러 플러그인머리에 탭; 마지막 선택 기억자리 하나를 공유

⑤ 에러 & 폴백

§3 매트릭스. 모양이 틀린 메시지는 응답 없이 무시(잡음에 응답하지 않음).

열려 있는 동안 플러그인이 바뀌면 (plugins.changed → PluginHost가 다시 목록을 받아 비교, 결정은 PluginHost):

변화열린 iframe 처리
rev만 바뀜 (코드·manifest 갱신, 권한 그대로)beforeClose(cap) → 새로 로드
권한이 늘어 pendingbeforeClose(cap) → 제거 → 그 자리에 켜짐 카드
invalid / incompatiblebeforeClose(cap) → 제거 → "This plugin can't load"
폴더 삭제(gone)즉시 제거(파일이 없어 저장할 곳도 없음) → 탭은 "Missing plugin"

PluginInfo.rev = manifest와 entry 파일의 mtime·크기로 만든 해시 (코어가 계산).

⑥ 동작 결과

플러그인 화면이 자리에 보이고, 데이터는 data/에 파일로 쌓인다.

⑦ 연결

S2 → S1 ↔ S3 → S4.

흐름 3: 종료 전 저장

① 트리거 & 타이밍

기존 app://flush (창 닫기·⌘Q). 지금 onBeforeQuitFlush는 동기 훅만 받으므로, appEvents에 비동기 훅 onQuitFlushAsync(fn: () => Promise<void>)를 추가하고 runQuitFlush가 이를 노트 flush와 병렬로 시작해 함께 await한다. 예산: 노트 몫 1.6 s 창을 공유하고 플러그인은 그 안에서 1.5 s cap (draft 400 ms·Rust 2.5 s 한도는 그대로). 패널 닫기·탭 떠나기도 같은 beforeClose(cap 1.5 s, 넘으면 그냥 제거).

② 워크플로우

  1. runQuitFlush가 등록된 훅 실행 → PluginHost.flushAll().
  2. 열린 iframe마다 beforeClose{id} → beforeClose.done{id} 대기 (Promise.allSettled + 타임아웃).
  3. 완료 또는 cap → flush_done.

③ 입력 & 출처

열린 iframe 목록(PluginHost 소유).

④ 주요 결정

cap 초과 시 기다리지 않음(결정론). 앱 종료를 플러그인이 막을 수 없다.

⑤ 에러 & 폴백

무응답·에러 → warn 로그, 종료 진행.

⑥ 동작 결과

디바운스 중이던 마지막 저장이 디스크에 반영된 뒤 종료 (AC-6).

⑦ 연결

onQuitFlushAsync(신규, appEvents) → PluginHost.flushAll → S1 beforeClose.

8. End-to-End Scenario 🟡

입력: 사용자가 rooms-plugin-excalidraw를 빌드해 ~/rooms/.rooms/plugins/excalidraw/에 복사 (permissions: clipboard, downloads). 이어서 Latency report 문서에 필기 → 문서를 Benchmarks에서 Research 방으로 옮김 → ⌘Q.

10.2 Senior Q&A

senior-review subagent 질문 + 답 (2026-10-06). 답에 따라 본문을 고쳤다.

Q1. fileKey breaks when plain files move

A. 맞다. 일반 파일 Artifact는 move_artifact가 파일을 실제로 옮겨 realpath가 바뀐다. 그래서 fileKey는 매번 계산하지 않고 처음 인덱싱할 때 정해 index 행에 저장하며, index.reassign이 행을 옮길 때 그대로 따라간다(§0 Glossary, §2 불변식 수정). Rooms 밖에서 옮기거나 이름을 바꾼 경우만 새 키 — 수용.

Q2. Can an iframe freeze the whole WKWebView?

A. 약속을 낮춘다. WKWebView는 iframe을 같은 메인 스레드에서 돌리므로 CPU를 독점하는 플러그인은 앱 전체를 멈출 수 있다. v1의 무응답 감지는 "메시지 루프가 멈췄지만 페이지는 살아 있는" 경우만 다룬다(AC-11 수정). 프로세스 분리(플러그인별 Tauri webview)는 실제 런타임 측정 후 v2 결정(§11).

Q3. Does the SDK verify inbound message source?

A. 예, 필수로 넣는다. SDK는 event.source !== window.parent인 메시지를 모두 버린다 — 옆 Artifact iframe이 parent.frames[i]로 context·응답·beforeClose를 위조하는 것을 막는다. §5 S1 상대편 보장에 추가했고, §9 SDK 단위 테스트에 "형제 프레임에서 온 가짜 context 무시"를 넣는다.

Q4. Concurrent instances of one plugin

A. v1에서는 생기지 않게 불변식으로 묶는다: 앱은 활성 탭 하나만 마운트하므로 한 창에서 한 플러그인 iframe은 최대 1개다(§2 추가). 따라서 조건부 쓰기·etag는 넣지 않는다(YAGNI). 에이전트가 밖에서 같은 파일을 고치는 경합은 last-writer-wins로 수용하고 §11의 변경 알림 질문으로 남긴다.

Q5. Who owns the "✎ Notes" toggle?

A. <PluginSlot slot="artifact.sidePanel">이 토글 버튼과 패널을 함께 그린다(닫혀 있으면 문서 오른쪽 위 토글만). 열림·너비·선택된 플러그인은 viewerStore의 pluginPanel 하나에 보는 사람 단위로 저장하며 탭·문서와 무관하다. 셸은 자리만 놓고 이 상태를 모른다(§5 S2 수정).

Q6. runQuitFlush only supports sync hooks

A. 계약을 바꾼다. appEvents에 onQuitFlushAsync(fn: () => Promise<void>)를 추가하고, runQuitFlush가 이를 노트 flush와 병렬로 시작해 함께 await한다. 플러그인은 노트의 1.6 s 창을 공유하며 그 안에서 1.5 s cap; draft 400 ms와 Rust 2.5 s 한도는 그대로(§7 흐름 3 수정).

Q7. Plugin CSP vs files-origin global header

A. 'self'를 쓰지 않고 경로 한정 출처 http://127.0.0.1:4318/_plugins/<id>/만 허용, frame-src 'none'·connect-src 'none'. /_plugins/*에는 지금의 전역 sandbox allow-scripts allow-popups를 적용하지 않고, manifest 권한에서 도출한 sandbox 토큰(필요 시 allow-downloads, popups 없음)을 붙인다. 정확한 헤더는 §2 규칙 6.

Q8. Manifest/code changes while a frame is open

A. 결정은 PluginHost가 plugins.changed 후 비교해서 한다: 코드·manifest만 갱신(rev 변경) → beforeClose 후 다시 로드, 권한 증가 → beforeClose 후 제거하고 켜짐 카드, invalid → beforeClose 후 "can't load", 폴더 삭제 → 즉시 제거. PluginInfo.rev(manifest·entry의 mtime·크기 해시)를 코어가 준다(§7 흐름 2 ⑤ 추가).
