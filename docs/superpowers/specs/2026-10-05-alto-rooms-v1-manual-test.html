Scenario 1 · Golden Path 설치부터 Journal 노트까지

전제: macOS, repo 체크아웃, Rust와 Bun 설치됨. 4317/4318 포트를 쓰는 다른 프로그램 없음(lsof -i :4317 -i :4318이 비어 있음).

  1. bun run --cwd apps/desktop sidecar && bun run --cwd apps/desktop tauri build --bundles app 후, apps/desktop/src-tauri/target/release/bundle/macos/Alto Rooms.app을 /Applications/Alto Rooms.app로 복사

    빌드가 Finished 1 bundle로 끝나고, 앱 안에 Contents/MacOS/roomsd가 들어 있음

    binaries/roomsd-<triple>가 없다는 오류면 sidecar 단계를 먼저 실행. 서명하지 않은 앱이므로 처음 열 때 Finder에서 우클릭 → 열기

  2. Alto Rooms를 처음 실행

    1~2초 안에 사이드바(Rooms, 찾기, Journal, 방 목록에 inbox)와 "지난 방문 이후" 새 탭이 보임. ~/rooms에 inbox, journal, .rooms/token(권한 600)이 생김

    "Rooms 코어를 시작하지 못했어요"가 보이면 lsof -i :4317로 포트를 누가 잡고 있는지 확인 (Scenario 6 참고)

  3. 사이드바 "방" 옆 +(새 방) → 연구 도구 입력 → Enter

    "연구 도구" 탭이 열리고 활성화됨. Clew 일러스트, "아직 아티팩트가 없어요", 폴더 경로 칩 ~/rooms/연구-도구가 보임. Finder에 ~/rooms/연구-도구 폴더가 생김

    "같은 이름의 방이 있어요" / "쓸 수 없는 이름이에요"가 뜨면 다른 이름으로. 아무 반응이 없으면 개발 빌드(bun run --cwd apps/desktop tauri dev)로 같은 단계를 재현하고 창에서 우클릭 → Inspect의 Console/Network 탭을 확인

  4. 경로 칩을 클릭

    "복사했어요"가 1.5초 보이고, 클립보드에 절대 경로가 들어 있음

  5. 에이전트(예: Claude Code)에게 "~/rooms/연구-도구에 오늘 조사한 내용을 HTML로 저장해 줘"라고 요청 (또는 터미널에서 echo '<title>첫 문서</title><h1>안녕</h1>' > ~/rooms/연구-도구/a.html)

    2초 안에 카드가 나타남: 미리보기, 제목, 검은 점(새 문서), 오른쪽에 오늘. 제목 아래 숫자가 문서 1로 바뀜

    카드가 안 보이면 curl -s 127.0.0.1:4317/v1/rooms에서 해당 방의 artifactCount를 확인. 숫자만 안 바뀌면 앱 쪽 문제, 목록에도 없으면 roomsd 감시 문제

  6. 카드에 마우스를 올리고 오른쪽 위 확대 버튼(새 탭에서 크게 보기)을 클릭

    문서 제목으로 된 탭이 열리고 문서가 패널 전체에 표시됨

  7. 사이드바 Journal 클릭 → "새 노트" 카드 클릭

    입력칸에 기본값 계획이 선택된 상태

  8. Enter → 본문에 - 할 일 입력 → 1초 기다림

    "계획" 노트 탭이 열림. ~/rooms/journal/<오늘>/계획.md에 - 할 일이 저장됨

    "저장하지 못했어요. 다시 시도할게요"가 보이면 journal/<오늘> 폴더 권한 확인

  9. 본문에 마지막 줄을 입력하고 바로 ⌘Q

    앱이 1초 안팎으로 종료되고, 계획.md에 마지막 줄까지 들어 있음. lsof -i :4317이 비어 있음 (roomsd도 종료)

    내용이 빠지면 종료 flush(app://flush → flush_done)가 동작하지 않은 것. 2.5초 뒤에야 닫히면 웹뷰가 응답하지 않은 것

종료 후 roomsd 프로세스가 남지 않음 (pgrep -fl roomsd 비어 있음)

Scenario 2 · Golden Path 메뉴와 단축키

전제: Scenario 1을 마친 상태에서 앱을 다시 실행.

  1. 메뉴 막대 확인

    Alto Rooms(About, Hide, Quit ⌘Q), Edit(Undo, Redo, Cut, Copy, Paste, Select All), 파일(새 탭 ⌘T, 탭 닫기 ⌘W, 창 닫기 ⇧⌘W)

  2. 방 탭이 열린 상태에서 ⌘W, ⌘T, ⌘B, ⌘K를 차례로

    ⌘W는 탭 하나만 닫음(두 개가 닫히지 않음), ⌘T는 새 탭, ⌘B는 사이드바 접기/펼치기, ⌘K는 "방이나 문서 찾기" 창

    ⌘W가 창 전체를 닫으면 메뉴가 기본 메뉴로 뜬 것. 탭이 두 개 닫히면 페이지와 메뉴가 둘 다 처리한 것

  3. 방 제목(h1)을 클릭해 이름을 고치는 중에 ⌘W, ⌘T, ⌘B

    아무 일도 일어나지 않고, 입력 중인 이름이 그대로 남음. ⌘K는 찾기 창을 엶

  4. 노트 본문에 입력하는 중에 ⌘W

    노트 탭이 닫힘. 다시 열면 방금 입력한 내용이 있음

  5. 입력칸에서 ⌘A, ⌘C, ⌘V, ⌘Z

    모두 평소처럼 동작 (Edit 메뉴)

  6. ⇧⌘W (창 닫기), 또는 빨간 닫기 버튼

    창이 닫히고 앱이 종료되며 roomsd도 사라짐

Scenario 3 · Edge Case Review Focus 1 — 재연결 중 변경

전제: 앱이 이미 실행 중인 roomsd를 재사용하므로, roomsd를 직접 띄워 끊었다 다시 켤 수 있음. 방 연구-도구에 a.html, b.html이 있음.

  1. 터미널 A: "/Applications/Alto Rooms.app/Contents/MacOS/roomsd" 실행 → 앱 실행 → "연구 도구" 탭 열기

    카드 a, b가 보임. pgrep -fl roomsd에 roomsd가 하나만 있음 (앱이 새로 띄우지 않고 재사용)

  2. 터미널 A에서 Ctrl-C로 roomsd 종료 → echo '<title>c</title>' > ~/rooms/연구-도구/c.html; rm ~/rooms/연구-도구/a.html

    앱 화면은 그대로 (변화 없음)

  3. 터미널 A에서 roomsd를 다시 실행하고 5초 기다림

    카드가 정확히 b, c — c는 한 번만, a는 사라짐. 제목 아래 문서 2

    c가 두 번 보이거나 a가 남으면 snapshot+seq 규칙 문제: 개발 빌드(bun run --cwd apps/desktop tauri dev)로 같은 단계를 재현하고 창에서 우클릭 → Inspect의 Console/Network 탭을 확인하고 /v1/events 재연결 뒤 /v1/rooms/<id>/artifacts 재요청이 있는지 확인

완료 체크

이 상태에서 방 이름 변경 같은 쓰기는 토큰이 바뀌어 실패할 수 있음 — 앱을 재시작하면 정상 (알려진 제한)

Scenario 4 · Edge Case Review Focus 2 — 탭이 열린 채 방 이름 변경

전제: "연구 도구" 탭이 열려 있고 카드가 하나 이상 있음.

  1. 제목(h1) 클릭 → 연구로 바꾸고 Enter

    탭 이름, 사이드바, 제목이 모두 "연구"로 바뀌고 ~/rooms/연구 폴더가 됨. 카드는 그대로

  2. Finder에서 그 폴더 이름을 연구 노트로 변경

    2초 안에 같은 탭(새 탭이 생기지 않음)의 이름이 "연구 노트"로 바뀌고 카드도 그대로

    탭에 "이 방은 더 이상 없어요"가 나오면 roomsd가 이름 변경을 삭제+추가로 처리한 것: curl -s 127.0.0.1:4317/v1/rooms에서 id가 유지되는지 확인

  3. 같은 이름의 방이 이미 있는 이름으로 변경 시도

    입력칸이 그대로 남고 아래에 "같은 이름의 방이 있어요" (빨간색, 아이콘)

Scenario 5 · Edge Case Review Focus 3 — 저장이 실패하는 동안의 노트

전제: 오늘 Journal에 "계획" 노트가 열려 있음.

  1. 터미널: chmod 555 ~/rooms/journal/<오늘> (폴더 쓰기 금지) → 노트에 실패 중 입력을 씀

    입력을 멈춘 뒤 0.8초에 첫 저장, 1초·2초 뒤 재시도. 세 번째 실패(약 4초)에서 "저장하지 못했어요. 다시 시도할게요"가 보임. 이후 4초, 그 다음부터 10초마다 재시도. 입력한 글은 그대로

  2. chmod 755 ~/rooms/journal/<오늘>로 되돌리고 최대 10초 기다림

    메시지가 사라지고 계획.md에 실패 중 입력이 들어 있음

    글이 사라졌거나 파일이 안 바뀌면 개발 빌드(bun run --cwd apps/desktop tauri dev)로 같은 단계를 재현하고 창에서 우클릭 → Inspect의 Console/Network 탭을 확인하고 PUT /v1/journal/…/notes/… 응답 확인

  3. 실패 상태(chmod 555)에서 노트 탭을 닫았다가 다시 열기

    입력한 글이 그대로 보임 (디스크의 옛 내용으로 덮이지 않음)

Scenario 6 · Edge Case Review Focus 4 — 악성 아티팩트 HTML

전제: 방 보안이 있음.

  1. ~/rooms/보안/evil.html에 다음을 저장: <title>수상한 문서</title><script>top.location='https://example.com'; fetch('http://127.0.0.1:4317/v1/rooms',{method:'POST',headers:{'content-type':'application/json'},body:'{"name":"x"}'}); parent.postMessage({type:'open'},'*')</script>

    "수상한 문서" 카드가 생김. 앱 화면이 다른 곳으로 이동하지 않음

  2. 카드를 크게 보기로 열고 1초 기다림

    앱은 그대로이고, 사이드바에 방 "x"가 생기지 않으며 ~/rooms/x도 없음. 탭이나 화면이 바뀌지 않음 (메시지 무시)

    "x"가 생겼다면 roomsd의 Origin/토큰 검사 문제. 앱이 이동했다면 iframe sandbox에 allow-top-navigation이나 allow-same-origin이 들어간 것

Scenario 7 · Edge Case Review Focus 5 — 이미 실행 중인 데몬 / 포트 점유

전제: 앱이 꺼져 있음.

  1. roomsd를 직접 실행한 뒤 앱 실행

    앱이 정상 동작하고 roomsd 프로세스는 하나뿐. 앱을 종료해도 직접 띄운 roomsd는 계속 실행 (앱이 띄운 것만 종료)

  2. roomsd를 끄고 python3 -m http.server 4317 --bind 127.0.0.1로 포트를 점유한 뒤 앱 실행

    약 5초 안에 "Rooms 코어를 시작하지 못했어요"와 "다시 시도" 버튼 (멈추지 않음)

    계속 빈 화면이면 시작 대기(5초 제한)가 동작하지 않은 것

  3. python 서버를 끄고 "다시 시도"

    앱이 roomsd를 띄우고 정상 화면으로 바뀜

Scenario 8 · Regression 인접 기능 영향 확인

왜: 이번 작업이 단축키 처리, 종료 과정, 방의 문서 수 계산을 바꿨기 때문.

    "결과가 없어요"

  2. 새 탭 화면

    "지난 방문 이후"와 방 카드. 방금 문서가 들어온 방은 "새 문서 n"과 함께 위쪽에. 각 카드의 문서 n이 실제 개수와 같음

  3. "기존 폴더 연결…"로 홈 밖의 폴더 연결

    네이티브 폴더 선택 창이 열리고, 선택한 폴더가 방으로 추가되어 탭이 열림
