Scenario 2 · Golden Path 메뉴와 단축키

전제: Scenario 1을 마친 상태에서 앱을 다시 실행.

  1. 메뉴 막대 확인

    Alto Rooms(About, Hide, Quit ⌘Q), Edit(Undo, Redo, Cut, Copy, Paste, Select All), 파일(새 탭 ⌘T, 탭 닫기 ⌘W, 창 닫기 ⇧⌘W), 보기(찾기 ⌘K, 사이드바 ⌘B)

  2. 방 탭이 열린 상태에서 ⌘W, ⌘T, ⌘B, ⌘K를 차례로

    ⌘W는 탭 하나만 닫음(두 개가 닫히지 않음), ⌘T는 새 탭, ⌘B는 사이드바 접기/펼치기, ⌘K는 "방이나 문서 찾기" 창

    ⌘W가 창 전체를 닫으면 메뉴가 기본 메뉴로 뜬 것. 탭이 두 개 닫히면 페이지와 메뉴가 둘 다 처리한 것

  3. 방 제목(h1)을 클릭해 이름을 고치는 중에 ⌘W, ⌘T, ⌘B

    아무 일도 일어나지 않고, 입력 중인 이름이 그대로 남음. ⌘K는 찾기 창을 엶

  4. 노트 본문에 입력하는 중에 ⌘W

    노트 탭이 닫힘. 다시 열면 방금 입력한 내용이 있음

  5. 입력칸에서 ⌘A, ⌘C, ⌘V, ⌘Z

    모두 평소처럼 동작 (Edit 메뉴)

  6. ⇧⌘W (창 닫기), 또는 빨간 닫기 버튼

    창이 닫히고 앱이 종료되며 roomsd도 사라짐

Scenario 5 · Edge Case Review Focus 3 — 저장이 실패하는 동안의 노트

전제: 오늘 Journal에 "계획" 노트가 열려 있음.

  1. 터미널: chmod 555 ~/rooms/journal/<오늘> (폴더 쓰기 금지) → 노트에 실패 중 입력을 씀

    입력을 멈춘 뒤 0.8초에 첫 저장, 1초·2초 뒤 재시도. 세 번째 실패(약 4초)에서 "저장하지 못했어요. 다시 시도할게요"가 보임. 이후 4초, 그 다음부터 10초마다 재시도. 입력한 글은 그대로

  2. chmod 755 ~/rooms/journal/<오늘>로 되돌리고 최대 10초 기다림

    메시지가 사라지고 계획.md에 실패 중 입력이 들어 있음

    글이 사라졌거나 파일이 안 바뀌면 개발 빌드(bun run --cwd apps/desktop tauri dev)로 같은 단계를 재현하고 창에서 우클릭 → Inspect의 Console/Network 탭을 확인하고 PUT /v1/journal/…/notes/… 응답 확인

  3. 실패 상태(chmod 555)에서 노트 탭을 닫았다가 다시 열기

    입력한 글이 그대로 보임 (디스크의 옛 내용으로 덮이지 않음)

Scenario 6 · Edge Case Review Focus 4 — 악성 아티팩트 HTML

전제: 방 보안이 있음.

  1. ~/rooms/보안/evil.html에 다음을 저장: <title>수상한 문서</title><script>top.location='https://example.com'; fetch('http://127.0.0.1:4317/v1/rooms',{method:'POST',headers:{'content-type':'application/json'},body:'{"name":"x"}'}); parent.postMessage({type:'open'},'*')</script>

    "수상한 문서" 카드가 생김. 앱 화면이 다른 곳으로 이동하지 않음

  2. 카드를 크게 보기로 열고 1초 기다림

    앱은 그대로이고, 사이드바에 방 "x"가 생기지 않으며 ~/rooms/x도 없음. 탭이나 화면이 바뀌지 않음 (메시지 무시)

    "x"가 생겼다면 roomsd의 Origin/토큰 검사 문제. 앱이 이동했다면 iframe sandbox에 allow-top-navigation이나 allow-same-origin이 들어간 것

Scenario 7 · Edge Case Review Focus 5 — 이미 실행 중인 데몬 / 포트 점유

전제: 앱이 꺼져 있음.

  1. roomsd를 직접 실행한 뒤 앱 실행

    앱이 정상 동작하고 roomsd 프로세스는 하나뿐. 앱을 종료해도 직접 띄운 roomsd는 계속 실행 (앱이 띄운 것만 종료)

  2. roomsd를 끄고 python3 -m http.server 4317 --bind 127.0.0.1로 포트를 점유한 뒤 앱 실행

    약 5초 안에 "Rooms 코어를 시작하지 못했어요"와 "다시 시도" 버튼 (멈추지 않음)

    계속 빈 화면이면 시작 대기(5초 제한)가 동작하지 않은 것

  3. python 서버를 끄고 "다시 시도"

    앱이 roomsd를 띄우고 정상 화면으로 바뀜

    "지난 방문 이후"와 방 카드. 방금 문서가 들어온 방은 "새 문서 n"과 함께 위쪽에. 각 카드의 문서 n이 실제 개수와 같음

  3. "기존 폴더 연결…"로 홈 밖의 폴더 연결

Scenario 9 · Edge Case 코어가 사라졌을 때

전제: 앱이 roomsd를 직접 띄운 상태(따로 실행한 데몬 없음). 노트 하나에 글을 쓰는 중.

  1. 터미널: pkill -x roomsd

    바로 "Rooms 코어를 시작하지 못했어요"와 "다시 시도" 버튼

    화면이 그대로면 daemon://exited가 안 온 것. 약 3초(재시도 2번) 뒤에는 떠야 함

  2. "다시 시도"

    roomsd가 다시 뜨고 탭들이 그대로 돌아옴. 끊기기 전에 쓰던 노트의 글이 디스크에 저장됨

  3. 노트 폴더를 chmod 555로 막고 글을 쓴 뒤 "저장하지 못했어요"가 뜨면 ⌘Q → 폴더를 chmod 755로 되돌리고 앱을 다시 열어 그 노트를 엶

    종료 전에 쓴 글이 보이고, 0.8초 뒤 저장됨

Scenario 10 · Golden Path 온보딩 — 에이전트로 처음 정리하기

전제: 최근 14일 안에 Claude Code로 HTML 파일을 몇 개 만든 적이 있음. 방이 inbox뿐인 새 홈(open --env ROOMS_HOME=$(mktemp -d) "/Applications/Alto Rooms.app")으로 실행. 실험 전 원본 몇 개의 ls -li와 shasum 결과를 적어 둠.

  1. 새 탭 화면 확인

    "Rooms에 오신 걸 환영해요" 환영 페이지와 "시작하기"의 프롬프트 칩 + 복사 버튼(<홈>/ONBOARD.md 를 읽고 따라 해줘, 홈이 ~/rooms면 ~/rooms/ONBOARD.md 를 읽고 따라 해줘). 홈에 ONBOARD.md(첫 줄 <!-- rooms-onboarding v3 -->)와 .rooms/onboarding/skill/rooms/가 생김

    카드 대신 "지난 방문 이후"가 보이면 홈에 이미 방이 있는 것. 빈 홈으로 다시 실행

  2. 칩 클릭 → Claude Code를 열고 붙여넣기 → Enter

    "복사했어요". 에이전트가 ONBOARD.md를 읽고 스킬을 설치한 뒤 find_html.py를 돌려, 후보 표와 제안 표(방, 새로/기존, 파일)를 한 번에 보여 주고 "이대로 만들까요?"라고 한 번 물음 (아직 아무 폴더도 만들지 않음)

    확인 없이 바로 폴더를 만들면 SKILL.md의 확인 단계를 건너뛴 것. 에이전트 출력을 저장해 두기

  3. 제안된 표를 확인하고 "예" (필요하면 방 이름을 고쳐 달라고 요청)

    2초 안에 사이드바에 새 방들이 생기고, 각 방에 카드가 보임. 어느 방에도 맞지 않는 문서는 inbox에. 에이전트가 만든 방, 방별 링크 개수, inbox 개수와 "원본 파일은 옮기지 않았어요. 링크만 만들었어요."를 알림. Finder에서 방 폴더의 파일은 모두 심볼릭 링크(ls -l에 ->)이고 원본 경로를 가리킴

    방이 안 보이면 curl -s 127.0.0.1:4317/v1/rooms로 확인. 링크가 아니라 복사본이면 스킬 규칙 위반

  4. 적어 둔 원본의 ls -li와 shasum을 다시 실행

    inode, 크기, 해시가 모두 같음. 원본 위치에 그대로 있음

    다르면 즉시 중단하고 에이전트 대화와 ls -l 결과를 보관 (원본은 절대 바뀌면 안 됨)

  5. Journal에서 오늘이 아닌, 원본을 만든 날짜로 이동

    링크된 문서가 원본을 만든 날에 보임 (링크를 만든 오늘이 아님)

  6. 같은 에이전트 세션(또는 새 세션)에서 rooms 정리해줘

    이미 링크된 문서(linked: true)는 다시 제안하지 않음. 그 사이 새 HTML이 없으면 새로 만들 것이 없다고 답함. 방과 링크가 중복으로 생기지 않음

    같은 문서의 링크가 두 번 생기면 find_html.py의 linked 판정 문제: python3 <홈>/.rooms/onboarding/skill/rooms/scripts/find_html.py --home <홈> 출력 확인

  7. 새 탭의 "방을 기다리는 문서"에서 한 줄을 끌어 사이드바의 방에 놓기

    놓는 동안 방이 테두리로 강조되고, 놓으면 목록에서 사라져 그 방에 카드로 나타남. 링크가 inbox/에서 그 방 폴더로 옮겨지고, 원본과 Journal 날짜는 그대로

    "옮길 수 없는 문서예요"가 뜨면 원본 방이나 대상 방이 연결된 방(linked)인지 확인. 줄을 끌 수 없으면 읽기 전용(다른 데몬에 연결) 상태인지 확인

  8. 첫 정리(3단계) 대화의 끝부분을 다시 확인

    에이전트가 ~/.claude/CLAUDE.md(Codex면 ~/.codex/AGENTS.md)에 - HTML 아티팩트를 만들면 rooms 스킬로 알맞은 방에 링크한다. 한 줄을 넣을지 한 번 물어봄. "예"일 때만 파일 끝에 한 번 추가

    묻지 않고 넣었거나 아예 묻지 않으면 SKILL.md의 마지막 단계 문제
